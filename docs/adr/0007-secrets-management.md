# ADR-0007: Secrets management

**Status:** Accepted

## Decision
- **No secret value is ever committed.** Git contains only `*.example` templates with `change-me` placeholders. gitleaks runs in pre-commit and CI with full history.
- **Compose:** `.env` is generated with random values by `scripts/dev.ps1 env` or `scripts/init-env.sh` (git-ignored, mode 600).
- **Kubernetes:** the `backend-secrets` Secret is generated by Terraform (`random_password` → `kubernetes_secret_v1`) or by `deployment/scripts/create-secrets.*`. Manifests only *reference* it.
- **Ansible:** secrets come from an Ansible Vault file; tasks handling them use `no_log: true`.
- **CI:** GitHub OIDC for registry auth and keyless signing, so there are no long-lived registry tokens.

## Production upgrade path
Replace generated Secrets with **External Secrets Operator** (Vault or a cloud secret
manager) or **Sealed Secrets**, enable etcd encryption at rest, and keep Terraform state in
an encrypted, access-controlled backend (the S3 backend config sets `encrypt = true`).

## Consequences
+ Leaking the repository leaks no credentials.
− Terraform state contains secrets and must be protected. It is git-ignored and documented.
